# JNU-CTG · план анализа и правила подготовки · v1

Дата: 17 октября 2026. Назначение: исследование дородовых КТГ для приложения ведения беременности. Источник: [Zenodo 21800730](https://zenodo.org/records/21800730), DOI 10.5281/zenodo.21800730; архив уже скачан в проект. Новая серия независима от UCI. Никакие метки и признаки двух баз не склеиваются.

## 1. Постановка

- Основная исследовательская задача: **FIGO normal / abnormal**, как размечено авторами. Отдельных suspect/pathologic здесь нет. Это экспертная оценка формы КТГ, не диагноз гипоксии и не вероятность неблагоприятного исхода.
- Отдельная вторичная задача: **neonatal_asphyxia**. 91 положительная пациентка; повторные записи не увеличивают число независимых исходов. Не заполнять неизвестные метки нулями или вычисленной по Апгар заменой.
- Приложение с произвольным больничным бланком требует подтверждения единиц и алгоритмов измерения. В этой серии первичный воспроизводимый путь идёт от цифровых сигналов, а опубликованные STV/LTV и нейросетевые признаки до уточнения происхождения остаются отдельным исследовательским представлением.
- Доступна одна клиника. Нельзя объявить внутренний holdout внешней клинической валидацией. Срок и интервал до родов на момент каждой записи не подтверждены; поле gestational_age не разрешает эту проблему.

## 2. Ноутбук 01 · глубокая подготовка данных — текущая задача

### Источник и схема

1. Проверить MD5/SHA-256, состав архива, CRC каждого прочитанного CSV, 20769 уникальных record_id, связь с 12606 patient_id, длину 7200 и каналы FHR/UC.
2. Проверить исходные названия столбцов, включая дубли заголовков, типы, текстовые заглушки и ошибки ввода. Сохранить исходную и нормализованную таблицы раздельно.
3. Проверить согласованность постоянных клинических сведений внутри patient_id. Имя файла не использовать как идентификатор пациентки или дату: фактическая структура требует проверки, общий временной суффикс не восстанавливает хронологию.
4. Составить для всех 215 столбцов реестр роли, доступности во времени и разрешения на использование. Выходы родов/Апгар/плацента, диагнозы с неподтверждённым временем и NetFea не входят в основной X.

### Клиническая таблица

5. Строго разобрать числа и булевы значения. «/», пустота и ошибка формата — разные причины пропуска; ничего не исправлять догадкой. Сохранить журнал исходных значений и причины нормализации.
6. Проверить диапазоны и целочисленность Апгар: сумма 0–10, компоненты 0–2. Проверить сумму компонентов при полной записи. Некорректные значения маскировать в очищенной копии, диагноз не переопределять автоматически.
7. Проверить перекрёстные ограничения: parity/gravidity, BMI/рост/масса, согласованность клинических меток. Не считать необычное значение автоматически ошибочным. Поля вторичной цели остаются nullable.

### Полный аудит сигналов

8. Просмотреть **все** 20769 записей. FHR=0/нечисловое/неположительное значение — не наблюдавшийся валидный FHR. UC=0 неоднозначно и не становится пропуском автоматически. Сохранить исходный сигнал в float32 memory map и компактные отдельные маски.
9. Посчитать долю/длины разрывов, скачки, экстремальные значения, плоские участки, уникальные значения и частоту UC=100. UC=100 не называть доказанным насыщением: в выпущенных сигналах встречаются уровни выше 100, единицы требуют проверки. Сохранить исходные значения. Для отдельной рабочей маски v1 задать широкий инженерный диапазон FHR 30–240 BPM: это предварительное правило обработки, не клиническая норма и не подтверждённый диапазон конкретного прибора. Точки вне него остаются в оригинале с отдельной причиной; сравнить дескрипторы с вариантом всех положительных FHR. Резкие изменения внутри диапазона не удалять автоматически. Записи целиком не удаляются; полностью отсутствующий пригодный FHR означает отказ/непригодность для обучения по сигналу.
10. Основные табличные дескрипторы вычислять по наблюдавшимся точкам. Для будущего signal pipeline разрешить линейное заполнение только внутренних разрывов ≤2 s; не экстраполировать края и не соединять длинные разрывы. Сохранить маску заполнения; провести чувствительность к 0/1/2 s на train. Порог — инженерная настройка v1, не клинический стандарт.
11. Проектные соседние/минутные/эпохальные дескрипторы назвать собственными именами с единицами. Они не являются точной реализацией STV/LTV производителя: исходный Doppler FHR не даёт истинного beat-to-beat RR и точных масок исключённых событий.
12. Сопоставить воспроизводимые mean/min/max/std с опубликованными F_* и несколькими вариантами обработки разрывов. Различие фиксировать как вопрос определения/предобработки, не объявлять автоматически ошибкой авторов.
13. Проверить точные дубли FHR и пары каналов, включая разные patient_id; сохранить конфликтующие метки. Все связанные patient_id объединить в одну единицу разбиения. Близкие повторы и перекрывающиеся записи требуют отдельного исследования, не обещать их отсутствие по одному SHA-256.

### Разбиение и подготовка

14. Зафиксировать **60/20/20 train/validation/test** по независимым компонентам patient_id и точных дублей. При 91 положительной пациентке это даёт примерно 55/18/18 положительных пациенток. Балансировать и FIGO-строки, и присутствие клинических исходов у пациенток, сохраняя естественную распространённость.
15. Выбрать лучший баланс из 64 детерминированных вариантов **только по размерам, группам и меткам**. Признаки, качество классификации и будущие предсказания не участвуют. Сохранить поддерживающие числа и абсолютные/относительные отклонения; несовпадения долей из-за целых групп не скрывать.
16. После фиксации не использовать test для выбора признаков, границ выбросов, порогов качества, скейлеров или вариантов заполнения. Разрешён только заранее заданный контроль целостности. Исследовательские графики распределений — train.
17. Основной X: версионированные наблюдаемые статистики сигналов; метки/ID/clinical outcomes/неподтверждённые published features отдельно. Маски качества — отдельный набор для последующей абляции. Табличные производные пропуски не считать нулями.
18. Сохранить необученный шаблон преобразований и подготовку, fit только на train: median imputer, RobustScaler, индикаторы пропуска **всех** столбцов, включая ранее не встречавшиеся пропуски. Для CatBoost оставить необмасштабированные значения. Для CV использовать clone шаблона и fit внутри каждого фолда, а не готовую матрицу после глобального train fit.
19. Для цифрового сигнала сохранить mean/std каждого канала, вычисленные только по наблюдавшимся train-точкам. Возвращать нормализованные каналы вместе с масками; числовая подстановка 0 после нормализации допустима только под явной маской отсутствия.
20. Сохранить первичный датасет, X/y/quality/splits, схемы, параметры обработки, SHA-256, версии, подготовленные train/validation/test матрицы и независимый validation receipt. Проверить roundtrip, отсутствие пересечения групп, параметры scaler/imputer и все ключевые инварианты.

## 3. Ноутбук 02 · семантика и интерпретируемые признаки — следующий этап

- Проверить определения доступных F_BL/F_A_N/F_D_N/F_STV/F_LTV и происхождение NetFea; выполнить проверку соответствия на тех же цифровых записях.
- Описать отдельный экстрактор событий с проверкой базальной линии и масок, не имитировать подтверждённый медицинский анализ прибора.
- Сопоставить признаки с типовыми отчётами разных устройств; оценить потерю информации при ограничении доступных полей. Не восстанавливать отсутствующую вариабельность из неподходящего агрегата.
- Разделить входы по доступности: сигнал, нативный отчёт, общий минимальный бланк. Для каждого — свой контракт и обучение.

## 4. Ноутбук 03 · обучение на FIGO

- Общие patient-grouped внешние/внутренние фолды. Dummy, регуляризованная логистика, CatBoost без/с весами, затем уместные signal-модели; одинаковые условия сравнения.
- Grid Search только внутри development; подбор состава признаков/предобработки внутри внутренних фолдов. Macro-F1, sensitivity, specificity, PR-AUC, ROC-AUC, PPV/NPV, log loss/Brier и patient-balanced оценки.
- Отдельные абляции: качество/маски, UC, краткое заполнение, опубликованные признаки после проверки, клинические сведения только с доказанным временем доступности.
- Калибровка и пороги без test. Ансамбль фолдов допускается по заранее заданному правилу на development. Калибровка должна соответствовать фактически экспортируемому ансамблю.

## 5. Ноутбук 04 · клинический исход — отдельная постановка

- Исключить только неизвестные/невалидные метки цели, сохранив журнал; не фильтровать по результату модели. Patient-level поддержка важнее 154 повторных записей.
- Проверить определения исхода и доступность признаков до предсказания, а также эффект неизвестного интервала КТГ→роды. Показать чувствительность результатов к выбору записи пациентки; хронология сейчас не восстановлена.
- Основной акцент на PR-AUC и operating points с доверительными интервалами по пациенткам. Сравнить с постоянной вероятностью и распространённостью, а не с высокой majority accuracy.
- При малой поддержке отказаться от сильных клинических выводов; рассчитанный риск нельзя объявить валидированным для реального приложения.

## 6. Проверка и перенос

Однократная финальная оценка закрытого test после фиксации моделей; интервалы по независимым пациентским компонентам, отдельный анализ подгрупп с достаточной поддержкой. Далее нужна независимая дородовая когорта другого центра/прибора, точное определение целевого сценария и проверка качества измерений. Трёхклассовую модель из бинарной разметки без новых меток не создавать.
