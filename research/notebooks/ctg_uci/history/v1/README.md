# КТГ · UCI Cardiotocography

Отдельная серия ноутбуков по [официальному набору UCI Cardiotocography](https://archive.ics.uci.edu/dataset/193/cardiotocography) (DOI 10.24432/C51S4N, CC BY 4.0). Исходный архив уже находится в `data/external/uci_cardiotocography/1.0.0/cardiotocography.zip`. Его SHA-256 зафиксирован в `data/registry/checksums.sha256`; Excel-книга извлекается автоматически при запуске первого ноутбука. Локальные массивы данных не хранятся в Git.

## Порядок

1. `01_prepare_data.ipynb` — чтение исходного XLS, сверка листов, аудит качества, распределения 20 числовых признаков и кодированной категории `Tendency`, первичная таблица, разбиение по исходным файлам с контролем долей `NSP` и `CLASS`, веса классов train и обучаемый только на train преобразователь. Скейлеры сохраняются отдельно в `scalers.joblib` и `scaler_parameters.json`.
2. `02_nested_grid_search.ipynb` — 5×3 grouped nested CV, полная сетка 24 комбинаций для A/B/C/D и простой линейный baseline, внутренние калибровка/пороги, выбор семейства.
3. `03_calibration_ensemble_and_test.ipynb` — финальный Grid Search на train, калибровка на validation, сравнение single и ансамбля пяти фолдов, фиксация решения, test и экспорт моделей.
4. `04_clustering_without_outcomes.ipynb` — Fuzzy C-Means, KMeans и GMM без меток в обучении/выборе; затем связь кластеров с экспертными классами на отложенных данных.
5. `05_results_and_error_analysis.ipynb` — сводка метрик, ошибки, PR/ROC, калибровка, групповые интервалы и проверка необходимости ансамбля.
6. `06_clustering_embeddings_grid_search.ipynb` — отдельное дополнение: UMAP, компактный denoising-автоэнкодер, PCA и контроль без сжатия; 1650 сочетаний с FCM/KMeans/GMM, выбор без меток, проверка геометрии и устойчивости, затем связь с NSP. Результаты 04 сохраняются побайтно.

Подробный протокол: [EXPERIMENT_PLAN.md](EXPERIMENT_PLAN.md). Разбиение 01 сохраняется; внутренние фолды существуют только внутри исходного train. Сохранённый scaler 01 не применяется как уже обученный к внутренним фолдам: для логистики и кластеризации он клонируется и оценивается заново. CatBoost работает без масштабирования. Результат grid search — лучший среди проверенных конфигураций, а не гарантия глобального оптимума.

## Запуск

Из корня проекта после `poetry install`:

```bash
poetry run jupyter lab research/notebooks/ctg_uci
```

Если архив отсутствует, загрузить только этот набор:

```bash
poetry run python -m src.data.download_open_datasets --dataset uci_cardiotocography_193
```

Ноутбук можно выполнить целиком штатной командой проекта: `poetry run python tools/execute_notebooks_inprocess.py research/notebooks/ctg_uci/01_prepare_data.ipynb`.

Аналогично выполнить 02, 03, 04 и 05 по порядку. Первый запуск 02/03 обучает все конфигурации; повторный использует checkpoint в `tmp/ctg_experiments/`, привязанные к исходным данным, коду и подготовленному преобразователю. Параллельно обрабатываются четыре конфигурации по два CPU-потока. Все таблицы, фолды и предсказания — в `research/experiments/ctg_uci/`; модели — в `models/exported/ctg_uci/`, включая `champion.joblib` и `model_card.json`. Модели и локальные checkpoint игнорируются Git.

Расчёты находятся в `src/training/ctg_experiments.py` и `src/training/ctg_clustering.py`; воспроизводимый генератор — `tools/build_ctg_training_notebooks.py`. Рекомендации по весам, OvR, иерархии и кластеризации рассмотрены в плане. Test не используется для изменения решения; ранее просмотренные распределения и стратификация не позволяют называть его новой слепой клинической когортой.

Дополнение 06 запускается после подготовки данных 01 и существующей кластеризации 04, независимо от повторного обучения классификаторов: `poetry run python tools/execute_notebooks_inprocess.py research/notebooks/ctg_uci/06_clustering_embeddings_grid_search.ipynb`. Оно требует `umap-learn` из обновлённого `poetry.lock`. Код — `src/training/ctg_embeddings.py`, генератор — `tools/build_ctg_embedding_notebook.py`; таблицы и рисунки — `research/experiments/ctg_uci/embeddings/`, полный bundle со скейлерами и редукторами — `models/exported/ctg_uci/clustering_embeddings.joblib`. Подбор использует общий validation silhouette по исходным файлам, а не экспертные классы или test. Устойчивость проверяется двумя дополнительными seed и пятью подвыборками 80% train-файлов. Повторное использование известного test явно обозначено как исследовательское.

Для прогноза использовать `champion.joblib`: он содержит проверку входов, модель/ансамбль, калибровку и порог. Отдельные `.cbm` содержат только деревья соответствующей головы и не заменяют полную процедуру.

## Выполненный эксперимент · 17 октября 2026

Все ноутбуки 02–05 выполнены. Вложенная сетка содержит 630 проверенных комбинаций «семейство × внешний фолд × параметры» и по три внутренних оценки на каждую; финальная сетка — ещё 126 комбинаций. Метрики независимо пересчитаны из сохранённых вероятностей, границы групп проверены в `validation_receipt.json`.

| Процедура | Train nested pooled macro-F1¹ | Test macro-F1² | Test recall P | Test AP P |
|---|---:|---:|---:|---:|
| A · MultiClass | 0.8601 | 0.8792 | 0.9143 | 0.9271 |
| B · SqrtBalanced | 0.8714 | 0.8657 | 0.9143 | 0.9207 |
| B · Balanced | 0.8508 | 0.8492 | 0.9143 | 0.9199 |
| C · OvR с калибровкой | 0.8680 | 0.8482 | 0.8286 | 0.9203 |
| D · иерархия | **0.8846** | 0.8656 | 0.9143 | 0.9264 |
| Логистика | 0.7325 | 0.7915 | 0.7714 | 0.8416 |
| Всегда normal | — | 0.2924 | 0.0000 | 0.0824 |

¹ Лучший допустимый способ postprocessing внутри nested CV. ² Способ postprocessing финальной модели выбран отдельно на validation; поэтому режимы CV и финальной модели могут различаться. `AP` — Average Precision; трапецеидальная PR-AUC приведена отдельно в 05.

До test выбрана **одиночная иерархия D**, без финальной калибровки: depth=5, iterations=300, learning_rate=0.1, l2_leaf_reg=10. Калибровка проверена, но raw-режим выиграл validation-сравнение. Ансамбль пяти иерархий улучшил validation macro-F1 лишь на 0.0066, ниже фиксированного порога 0.01. На test у него macro-F1 0.8490 и recall P 0.8286 — преимущество averaging не подтвердилось.

Чемпион нашёл 32 из 35 патологических сегментов; один ошибочно отнёс к normal, два — к suspect. Групповой 95% интервал macro-F1: 0.7676–0.9218; recall P: 0.6957–1.0000. Эти 35 сегментов относятся всего к 10 файлам, поэтому точность оценки ограничена. Обычный A на данном test лучше по macro-F1; ранжирование не совпало с CV. Это сохранено в отчёте и не использовано для переименования заранее выбранного чемпиона. Глобальное превосходство D не установлено.

FCM, KMeans и GMM выбрали по 2 кластера без меток; test ARI соответственно 0.0741, 0.0913 и −0.0024. FCM даёт доли P 6.9% и 9.4% против общего уровня 8.2%; интервалы обогащения **патологией** всех алгоритмов включают 1. Отдельные патологические группы не подтверждены.

При этом FCM разделяет подозрительные паттерны: suspect 27.2% против 1.3%. В кластере 0 suspect обогащён примерно в 2.00 раза (групповой интервал 1.59–2.70), а abnormal=NSP>1 — в 1.56 раза (1.11–2.08). Это исследовательское уточнение после просмотра таблицы состава; параметры кластеров не менялись. Оно требует независимой проверки и не означает обнаружения всех трёх клинических уровней риска. Кластеры не добавлялись задним числом как «улучшающий» supervised-признак.

Выходы описаны в [контракте данных](../../../data/processed/ctg_uci/DATASET.md). Главная метка `NSP` означает экспертный класс КТГ (1 — normal, 2 — suspect, 3 — pathologic), а не наблюдаемый исход ребёнка. `CLASS` — другая экспертная метка, не входящая в признаки. Разбиение исключает пересечение сегментов одного исходного файла и одинаковых feature-векторов, но не доказывает независимость пациенток: идентификатора женщины нет.

В исходном снимке нет пропусков, поэтому модель не обучается на их масках или импутации; новый пропуск вызывает ошибку входного контракта. `DS` остаётся в первичных данных, но исключён из модельной матрицы из-за недостатка исходных записей с ненулевым значением. `Width` также остаётся в первичной таблице, но исключён из масштабированной матрицы как точная разность `Max−Min`.

Для повторного преобразования загружайте `preprocessor.joblib` из корня проекта в окружении из `poetry.lock` и передавайте `DataFrame` ровно с 21 исходным признаком, перечисленным в `manifest.json`. Файл `scalers.joblib` содержит те же обученные скейлеры отдельно; порядок их применения задаёт полный преобразователь.

## Выполненное дополнение 06 · сжатие и кластеризация

Выполнены 55 представлений и 1650 сочетаний с настройками кластеризации, затем 84 повторных обучения для диагностики устойчивости. Все 9 прежних файлов кластеризации, включая ноутбук 04 и его модель, сохранили SHA-256. Полные таблицы и рисунки находятся в `research/experiments/ctg_uci/embeddings/`.

| FCM · представление | Выбранные настройки сжатия | Test ARI с NSP |
|---|---|---:|
| Прежний PCA 90% из 04 | 10 компонент | 0.0741 |
| Новый контроль без сжатия | 21 подготовленный столбец | 0.0764 |
| Новый PCA | 2 компоненты | 0.0483 |
| UMAP | 5 компонент, 30 соседей, min_dist=.1 | −0.0104 |
| Denoising AE | 2 компоненты, ширина 16, ReLU, alpha=.001, 842 эпохи | 0.0641 |

Все выбранные решения имеют k=2; число кластеров не задавалось равным числу экспертных классов. Вариант AE+GMM даёт более высокий описательный test ARI 0.2159 и кластер с 20/45 патологическими сегментами (44.4%). Однако эти случаи происходят всего из двух исходных файлов; точечный интервал обогащения 0–8.52 включает 1. При двух дополнительных seed ARI совпадения validation-назначений AE+GMM равен −0.010–0.075: решение неустойчиво. Ни один выбранный кластер не имеет точечного интервала обогащения патологией целиком выше 1. Устойчивое улучшение выделения экспертных классов от нелинейного сжатия на этом эксперименте не подтверждено.

Автоэнкодер использует остановку по реконструкции на 46 отдельных файлах внутри train, с собственными внутренними скейлерами, затем переобучение на всех 227 train-файлах ровно выбранное число эпох. Изначальные 300 эпох оказались недостаточны; бюджет расширен до 1200 по диагностике реконструкции, без использования NSP. Параметры подбирались по общей геометрии validation без меток. Test уже известен исследованию; эти сопоставления требуют независимого подтверждения.
