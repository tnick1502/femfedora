# Ввод КТГ в приложение для ведения беременности

## Что готово

Выполненный ноутбук **08_hospital_reports_feature_engineering.ipynb** разбирает исходные признаки, реальные единицы и определения, проверяет новые признаки и обучает отдельные модели на ограниченных входах. Предыдущие эксперименты сохранены.

Общий формат ввода: `data/processed/ctg_uci/report_features_v1/hospital_report_template.json` и такой же CSV. Пример заполнения: `example_report_transcribed.json`. Пример записи для приложения: `example_app_record.json`.

У неизвестного аппарата данные можно сохранить. Отсутствующее значение — `null`, измеренный ноль — `0`. Отдельно хранятся аппарат/ПО, срок и контекст записи. Единицы зафиксированы в названиях полей.

## Минимальные поля

| Поле | Единицы / смысл |
|---|---|
| `duration_min` | Длительность именно анализируемого интервала, минуты |
| `baseline_bpm` | Базальная ЧСС, уд./мин |
| `accelerations_15_15_count` | Число акцелераций по указанному на бланке порогу 15 BPM / 15 s |
| `decelerations_15_15_count` | Число всех децелераций по указанному порогу |
| `signal_loss_pct` | Процент потерь; если неизвестен — null |
| `stv_ms` | STV в ms; сохраняется с происхождением, не подменяет UCI MSTV |
| `analysis_context` | `antenatal` / `intrapartum` / `unknown` / null |
| `gestational_weeks` | Срок на момент записи, не срок при родах |
| `device`, `software_version` | Могут быть неизвестны; неизвестность не заполняется догадкой |

Остальные поля шаблона сохраняют ВКИ, LTV/амплитуду, вариабельность, движения, синусоидальный ритм и альтернативные пороги отдельно. Значения без подтверждённой семантики не подаются в модель. Не объединять акцелерации >10 и >15 и не заменять «20 потерянных ударов» на «20 BPM».

## Использование

`src.features.ctg_pregnancy_app.prepare_pregnancy_app_record(record)` принимает неполные данные и возвращает исходные значения, маску пропусков и доступные преобразования единиц. Неизвестный аппарат не мешает хранению. `clinical_risk` остаётся null, автоматическое медицинское предсказание отключено: внешняя дородовая валидация отсутствует.

`src.features.ctg_report_features.report_to_common3(record)` дополнительно требует подтверждённый нативный контракт измерений. Флаг совместимости не означает клинической пригодности. Для неизвестного больничного отчёта этот путь отклоняет inference.

Результат распознавания фотографии требует сверки человеком: единицы, десятичные знаки, порог события, длительность и фактическое отсутствие измерения. В этой работе выполнена ручная транскрипция одного изображения; универсальный OCR не заявлен.

## Почему нет универсального медицинского класса

Обучение только на трёх условно общих признаках дало на известном test macro-F1 0.546 и нашло 12/35 патологических сегментов (34.3%); precision патологического класса 17.6%. У native SisPorto9 macro-F1 0.844 и 31/35 (88.6%), но в обычном бланке нужные измерения отсутствуют. Test ранее использовался в исследовании, поэтому эти цифры не являются новой внешней проверкой.

Одни и те же LB/AC/общая частота децелераций в train встречаются с разными NSP: 302 сегмента попадают в группы с неоднозначной меткой. Производные от этих трёх чисел не восстанавливают утраченную временную вариабельность. Для нормальной модели приложения нужны размеченные дородовые записи с проверенными измерениями, независимыми ID пациенток и внешней проверкой на целевых устройствах.

Все три исследовательских bundle, схема, калибровка и экспорт подготовки сохранены в `models/exported/ctg_uci/report_features_v1/`. Они не подключены к клиническим решениям приложения.
