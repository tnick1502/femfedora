# Верификация, приёмка и контроль рисков

Точность модели не является достаточным доказательством качества продукта. Для каждого релиза нужны связанные требования, тесты, доказательства и владелец риска.

## Обязательный пакет доказательств

- воспроизводимая сборка, версии зависимостей и SBOM;
- словарь данных, terminology map, event schema и миграции;
- реестр правил с источниками, версиями и golden cases;
- data sheets и model cards;
- point-in-time feature pipeline и автоматические leakage-тесты;
- отчёт разработки/валидации по TRIPOD+AI и оценка риска смещения по PROBAST+AI;
- для ранней клинической оценки — протокол в логике DECIDE-AI;
- timeline, карточки и очередь ручной проверки;
- audit, RBAC/ABAC, backup/restore, monitoring и incident runbook;
- обезличенный экспорт для независимой статистической проверки;
- руководство пользователя и протокол обучения персонала.

## Матрица требования и доказательства

| Требование | Реализация | Проверка | Доказательство |
|---|---|---|---|
| Правильный GA | Dating service | эталонные даты, смена метода и пересчёт | протокол теста |
| Воспроизводимый ВТЭО | Rule Engine config | golden clinical cases | 100% совпадение |
| Нет утечки | `available_at` filter | синтетические future events | CI log |
| Безопасный отказ | abstention policy | OOD и critical missing | UI + audit event |
| Откат модели | model registry | rollback drill | runbook и журнал |

## Минимальные golden scenarios

| ID | Сценарий | Ожидаемое поведение |
|---|---|---|
| `VTE-01` | первый визит, все факторы введены | детерминированный результат, причины и дата повторной оценки |
| `VTE-02` | новая госпитализация | автоматический пересчёт без удаления старого результата |
| `PE-01` | АД на обеих руках и повтор | первичные значения видимы; правило выбора документировано |
| `PE-02` | лаборатория готова после index time | не входит в старый прогноз; после готовности создаёт новый расчёт |
| `PTB-01` | предыдущие PTB с неизвестным сроком | пропуск не становится `false`; создаётся запрос уточнения |
| `ICN-01` | серийная цервикометрия | траектория по GA; несопоставимый метод отмечен |
| `FGR-01` | двойня | биометрия не смешивается между плодами |
| `FGR-02` | смена стандарта центилей | новая версия; старый расчёт воспроизводим |
| `CTG-01` | высокая потеря сигнала | `abstain` до классификации |
| `SYS-01` | событие связано с другой беременностью | блокировка и ручная очередь |
| `SYS-02` | модель вне области применимости | правило остаётся; ML скрыт или помечен `abstain` |

Golden suite расширяется клинической командой. Изменение правила не принимается, пока предыдущие сценарии не воспроизводятся или не изменены формальным решением с новым источником.

## Реестр ключевых рисков

| Риск | Контроль | Владелец |
|---|---|---|
| утечка будущего | `available_at`, point-in-time tests, temporal split | Data/ML |
| неверная беременность | linkage confidence, abstain, manual review | Data/Clinical |
| неверная единица | unit dictionary, диапазоны, исходное значение | Backend/QA |
| подмена SGA и FGR | отдельные labels, definitions и claims | Clinical/ML |
| treatment leakage/confounding | index time, causal review, sensitivity analysis | ML/Clinical |
| dataset shift относительно РФ | локальная калибровка и external validation | Product/ML |
| automation bias | provenance правила, uncertainty, disagreement UI | Design/Clinical |
| parser hallucination | C3 confirmation и source spans | NLP/QA |
| редкое ВТЭО | rule-only, multicenter data, no ML claim | Clinical/Product |
| регуляторная переклассификация | intended use и ранняя regulatory review | Regulatory |

## Проверка parser

Средний F1 не скрывает ошибки редких критических полей. Для каждого C2/C3-поля отдельно измеряются precision, recall, unit accuracy, date/GA accuracy, hallucination rate и ручные исправления.

Ручная очередь обязательна при конфликте единиц, биологически невозможном значении, конфликте даты/GA, неоднозначной беременности, изменении категории карточки и извлечении C3-факта только из свободного текста. Исправление сохраняет исходный parser output и автора подтверждения.

## Методологические инварианты

- калибровка оценивается intercept, slope, Brier и графиком, а не одной ECE;
- коэффициент логистической модели интерпретируется как отношение шансов только при прочих равных;
- class weights не исправляют калибровку автоматически;
- spontaneous и indicated PTB требуют competing-risks постановки, если причина доступна;
- bootstrap выполняется на уровне женщины, записи или центра, а не отдельных строк/окон;
- до клинического утверждения hybrid gate оставляет правило главным и включает abstain при плохих данных;
- PSI является лишь одним индикатором дрейфа;
- агрегированный quality score не скрывает первичные флаги качества.

## Нефункциональная приёмка

- детерминированный пересчёт правила и повторяемый inference по версии;
- отдельные SLO для online и batch inference;
- нулевая потеря исходного события при исправлении;
- monitoring latency, errors, missingness, drift, abstention и overrides;
- экспорт полного объяснения одного расчёта;
- проверенный backup/restore и аварийный режим без ML;
- независимый rollback правила, parser, модели и интерфейса.
