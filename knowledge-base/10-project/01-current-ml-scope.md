# Текущий ML-scope

## Решение на текущий этап

Сейчас проект ограничен исследовательскими ML-моделями и подготовкой воспроизводимых данных. Полный клинический продукт из [[00-product-canon|эталона продукта]] остаётся направлением развития, но не входит в ближайший implementation scope.

Это осознанное сужение разделов 19 и 22 исходной спецификации, а не удаление Event Store, Care Plan или rule cards из продуктового замысла. Полная сверка приведена в [[06-source-traceability]].

## Три приоритетных кандидата

| Приоритет | Задача | Почему ML уместен | Стартовая модель |
|---|---|---|---|
| P0 | Преэклампсия и гипертензивные нарушения | Риск зависит от динамики давления, протеинурии, почек, печени и контекста лечения | регуляризованная логистика на landmark; затем calibrated GBM |
| P0 | Преждевременные роды | Естественная задача исхода и времени до события | логистика PTB `<37`/`<32`; затем discrete-time survival |
| P0 | КТГ; EHG как R&D | Длинный временной сигнал оправдывает signal-модели | ручные признаки → логистика → 1D-CNN/TCN; SSM/Mamba только challenger |

## Потенциальные задачи после накопления данных

| Задача | Что делать сейчас | Условие перехода к ML |
|---|---|---|
| ИЦН | Создать карточку и собирать серийную цервикометрию, вмешательства и исходы | локальная или контролируемая когорта с достоверным фенотипом |
| ЗРП/FGR | Реализовать детерминированные центили; собирать серии УЗИ и допплер | достаточное число траекторий с качеством измерений и исходами |
| ГСД/GDM | Порог ОГТТ оставить правилом; сделать простой ранний baseline | отдельная временная когорта, где predictors гарантированно предшествуют диагнозу |

## Ограничение сложности

На текущем этапе используются лёгкие, проверяемые модели:

1. регуляризованная логистика;
2. Cox или discrete-time hazard для времени до события;
3. градиентный бустинг только после честной логистической baseline;
4. ручные signal-features и логистика для КТГ/EHG;
5. 1D-CNN/TCN после проверки качества и label contract;
6. SSM/Mamba — только после сильного baseline и только для действительно длинных последовательностей.

Для 8–15 визитов преимущество Mamba не предполагается заранее. Для десятков тысяч точек КТГ вычислительная мотивация есть, но клинический claim всё равно определяется outcome и валидацией.

## Definition of done ближайшего этапа

- скачаны и зарегистрированы открытые данные;
- у каждого набора есть лицензия, контрольная сумма и data card;
- task specification отделяет index time, horizon, outcome, predictors и exclusions;
- baseline выполняется воспроизводимо;
- train/validation/test разделены по пациенту/записи и времени;
- опубликованы AUROC, AUPRC, Brier, calibration slope/intercept и confusion counts;
- ограничения открытого набора явно запрещают клиническую интерпретацию там, где её нет.

## Не входит в текущий scope

- интерфейс клинических карточек;
- интеграция с МИС;
- автоматическая тактика;
- локальная клиническая валидация;
- обучение на контролируемых nuMoM2b/NICHD данных до получения разрешения.
