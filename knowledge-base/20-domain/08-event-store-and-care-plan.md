# Pregnancy Event Store и Care Plan

Эта заметка фиксирует основу продукта, на которой позже работают правила и модели. Календарь наблюдения, первичные клинические факты и вычисленные признаки — разные слои и не подменяют друг друга.

## Иерархия и grain

| Сущность | Кардинальность | Смысл |
|---|---:|---|
| `Person` | 1 | пациентка и устойчивый идентификатор |
| `PregnancyEpisode` | 0..N | отдельная беременность, датировка, ПДР и исход |
| `Fetus` | 1..N на беременность | раздельные УЗИ и исходы при многоплодии |
| `Encounter` | 0..N | визит, госпитализация или телемедицинский контакт |
| `ClinicalEvent` | 0..N | измерение, лаборатория, диагноз, препарат, процедура или документ |
| `Outcome` | 0..N | исход с определением, временем, источником и подтверждением |

Нельзя превращать пациентку в одну строку или смешивать события разных беременностей и плодов.

## Время и датировка

- `observed_at` — когда событие произошло или образец был получен;
- `available_at` — когда результат стал доступен системе и врачу;
- `ga_days` — гестационный возраст на дату события, вычисленный из версионируемой опорной датировки;
- `dating_method`, `dating_anchor`, `EDD` и `confidence` сохраняются вместе;
- раннее УЗИ, ПМ и ЭКО/перенос эмбриона не смешиваются молча;
- пересчёт ПДР создаёт новую версию, но не переписывает старые прогнозы;
- конфликт датировки отображается явно и может переводить расчёт в `MANUAL_REVIEW`.

Point-in-time правило подробно закреплено в [[05-data-and-prediction-contracts]].

## Первичные измерения

АД на разных руках и повторы являются отдельными событиями. Для каждого значения нужны рука, положение, размер манжеты, устройство, порядок и номер повтора. Производное среднее вычисляется по заранее утверждённому правилу, а исходные значения сохраняются.

Вес хранится на каждом визите с единицей, условиями измерения, источником и связью с беременностью. BMI и другие производные признаки не заменяют первичные рост и вес.

## Care Plan — отдельный слой

Care Plan отвечает на вопрос, какое обследование ожидается, в каком гестационном окне и при каком условии. Он не является готовой матрицей признаков ML.

### Базовые контрольные окна

| Период | Ожидаемые группы событий |
|---|---|
| 1–13 недель | базовые анализы; инфекции и иммунология; УЗИ/PAPP-A/свободный β-ХГЧ; НИПТ по показаниям; осмотры |
| 14–27 недель | цервикометрия 15–24 недели у группы риска; скрининг 19–20 недель; Rh-контроль; белок мочи; ОГТТ 24–28 недель; ОАК/ферритин |
| 28 недель — роды | Rh-контроль; УЗИ роста; допплер по показаниям; КТГ с 32 недель; GBS 35–37 недель; повторные лаборатории по протоколу |

Это структурный шаблон продукта, а не самостоятельная медицинская рекомендация. Точные окна, условия и действия активируются только из утверждённой версии клинического источника и локального регламента.

### Состояния задачи

| Статус | Значение |
|---|---|
| `planned` | окно ещё не наступило |
| `due` | окно наступило |
| `completed` | валидный результат связан с задачей |
| `overdue` | окно завершилось без результата |
| `not_applicable` | условие не выполнено; основание сохранено |
| `declined/deferred` | отказ или перенос с причиной, автором и новой датой |

Причина отсутствия кодируется отдельно: срок ещё не наступил, решение врача, отказ пациентки, недоступность, потеря наблюдения или ошибка данных. Отсутствие результата не превращается в отрицательный клинический факт.

## Минимальный словарь данных

| Домен | Обязательный минимум |
|---|---|
| Идентичность | `person_id`, `organization_id`, `pseudonym_id` |
| Беременность | `pregnancy_id`, `plurality`, `dating_method`, `dating_anchor`, `EDD`, `confidence` |
| Плод | `fetus_id`, `fetus_label`, хориальность/амниальность |
| Событие | concept, value, unit, `observed_at`, `available_at`, `ga_days`, status, source |
| Измерение | device, operator, method, laterality, position, `repeat_no`, quality |
| Лаборатория | specimen, method, reference interval, abnormal flag, accession |
| УЗИ | parameter, `fetus_id`, method/formula, image/report link, operator, quality |
| Карточка | `card_id`, `rule_version`, `model_version`, `inputs_hash`, result, reasons, abstain |
| Исход | `definition_id`, date/GA, source, `confirmation_status`, adjudicator |
| Действие | `recommendation_ref`, `clinician_decision`, `override_reason`, `completed_at` |

## Инварианты

1. Исправление создаёт новую версию события и не удаляет исходное значение.
2. Значение без единицы, времени, беременности или происхождения не становится молча модельным признаком.
3. Биометрия многоплодной беременности всегда привязана к конкретному `fetus_id`.
4. Сгенерированное или восстановленное моделью значение не записывается как измеренный факт.
5. Ошибка linkage между беременностями блокирует расчёт и создаёт ручную задачу.
