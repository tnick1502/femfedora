# EMO Core

Самостоятельный backend эмоциональной поддержки во время беременности и после родов. Python 3.12–3.14, FastAPI, PostgreSQL 16, SQLAlchemy и Alembic. Для генерации используется OpenAI-совместимый API, для Jev — TypeSafe SDK. Планировщик работает отдельным процессом с очередью в PostgreSQL.

У проекта свои Poetry-конфигурация, lock-файл, `.venv`, Docker-образы и данные. Импортов из родительского проекта нет. Исходное задание сохранено в [docs/ORIGINAL_SPEC.md](docs/ORIGINAL_SPEC.md), текущая сверка — в [docs/IMPLEMENTATION.md](docs/IMPLEMENTATION.md).

## Запуск

Команды выполняются из папки `emo_core/`. Нужны Poetry 2.x, Python подходящей версии и Docker с Compose.

```bash
poetry install
poetry run emo-config init-env
docker compose up --build -d
```

`init-env` создаёт `.env` по [шаблону](.env.example), заполняет недостающие локальные секреты и устанавливает права `0600`. Заполненные значения сохраняет; секреты в терминал не выводит. Для существующей установки команда повторно безопасна.

После запуска доступны:

| Адрес | Назначение |
|---|---|
| [http://127.0.0.1:8086/demo/](http://127.0.0.1:8086/demo/) | Тестовый клиент |
| [http://127.0.0.1:8086/docs](http://127.0.0.1:8086/docs) | Swagger |
| [http://127.0.0.1:8086/openapi.json](http://127.0.0.1:8086/openapi.json) | Контракт API |
| [http://127.0.0.1:8086/health](http://127.0.0.1:8086/health) | Проверка API и соединения с БД |

Сервис `migrate` применяет миграции до старта API и worker. HTTP-порт задаётся `EMO_HTTP_PORT`, PostgreSQL наружу не публикуется. Данные находятся в volume проекта `emo-core`.

```bash
docker compose logs --tail=30 api worker
docker compose down
```

Остановка сохраняет БД. `docker compose down --volumes` удаляет её данные; эта команда нужна только для сброса расходуемого стенда.

## Развёрнутый сервер

Стенд доступен по [HTTPS на 81.31.245.115](https://81.31.245.115/demo/). Вход использует `APP_LOGIN` и `APP_PASSWORD` из локального `.env`. На сервере работают реальные `deepseek-flash` и `jev-1.14.0`; текущий режим development/live и клинические ограничения сохранены.

Пути установки, команды обновления, автозапуск, HTTPS и резервное копирование описаны в [docs/SERVER_DEPLOYMENT.md](docs/SERVER_DEPLOYMENT.md). Секреты в Git и Docker-образ не включены.

## Вход и токены

Серверные секреты задаются в `.env`: `APP_LOGIN`, `APP_PASSWORD`, `ADMIN_API_TOKEN`, `MODEL_SECRETS_KEY`, `LLM_API_KEY`, `TYPESAFE_API_KEY`, `DEMO_JWT_SECRET`, `POSTGRES_PASSWORD` и `DATABASE_URL`. Полный справочник, дополнительные ключи и порядок смены настроек — в [docs/CONFIGURATION.md](docs/CONFIGURATION.md). Файл с реальными значениями исключён из Git и Docker build context.

Если заданы логин и пароль, `POST /auth/login` выдаёт сессию консоли на 8 часов по умолчанию. Она разрешает выпуск демо-токенов и администрирование. Альтернативный доступ администратора — заголовок `X-Admin-Token`. Пользовательский JWT этих прав не даёт.

В development/test доступны два независимых профиля: `anna` и `maria`. `POST /dev/token` с `{"user":"anna","purpose":"session"}` выдаёт JWT на два часа; `purpose: "api"` — на `API_KEY_TTL_DAYS` (по умолчанию 30 дней). При включённом входе запрос требует Bearer-токен консоли. Выпуск профиля также требует `DEMO_AUTH_ENABLED=true`.

В production токены пользователей выпускает основное приложение: EMO проверяет RS256, JWKS, издателя, аудиторию и срок. Демо-вход и mock запрещены. Порядок интеграции описан в [docs/API.md](docs/API.md).

## Модели и отчёты решений

`AI_MODE=mock` включает локальные демонстрационные ответы без сети. `disabled` отключает внешние модели и использует ограниченные шаблоны. `live` обращается к настроенным LLM и Jev. Для live нужны разрешение оператора, ключи, регион обработки, разрешённые HTTPS-хосты и личное согласие пользователя.

Администратор создаёт и меняет общие профили LLM/Jev через API реестра. Ключ можно оставить в `.env` и выбрать по имени либо передать backend для шифрования Fernet. Выбор действует на следующие сообщения всех пользователей без перезапуска; текущая обработка и старые отчёты сохраняют свой снимок конфигурации. Настройка и примеры запросов — в [справочнике конфигурации](docs/CONFIGURATION.md#общие-модели).

Каждый новый ответ чата содержит `metadata.decision_report`: модели и ревизию, результаты Jev, причины маршрута, выбранную потребность, запрошенный и применённый протокол, проверки ответа, fallback, число вызовов и время этапов. Отчёт также доступен владельцу через отдельный endpoint. Он отражает выполненные правила и результаты проверок; промпты, текст переписки и секреты в него не включаются. Старым сообщениям отчёты задним числом не добавляются.

В обычных логах остаются технические события, Trace ID и метрики. Отчёт решения хранится с сообщением и относится к данным пользователя.

## API и тестовый клиент

Префикс пользовательского API — `/api/v1/emo`. Основные ресурсы: беседы и сообщения, память, жалобы, check-in, журнал, динамика, опросники, настройки, контакты помощи и согласованные будущие сообщения. Владельца определяет JWT; `user_id` из JSON не принимается. Чужой UUID возвращает тот же 404, что и отсутствующий.

[Справочник API](docs/API.md) содержит маршруты, повторы запросов и ошибки. [Контракт опросников](docs/QUESTIONNAIRE_API.md) описывает start → PATCH → complete, ревизии и обработку safety-пунктов.

`demo/` — статический тестовый клиент этого API. Backend можно использовать из основного приложения или отдельного HTTP-клиента. Для консольного прохождения опросника:

```bash
cp examples/client.env.example examples/client.env
chmod 600 examples/client.env
# Заполнить EMO_API_TOKEN в examples/client.env.
poetry run python examples/questionnaire_client.py --code PHQ9
```

## Опросники и ограничения

В поставке есть русские PHQ-9, GAD-7, EPDS и City Birth Trauma Scale. PHQ-9/GAD-7 — постоянное ядро; EPDS добавляется при беременности, EPDS/City BiTS — после родов. PASS-R отключена по текущему заданию. GAD-2 снята с использования; история сохраняется. Вопросы, варианты, ключи, пороги, источники и основания использования сохранены в [описании новой логики и источников](docs/CLINICAL_DESIGN.md). Суммы считает Python без AI. Попытка хранит снимок редакции и хеш; завершённый результат неизменяем. Safety-пункты проверяются уже при сохранении черновика, независимо от суммы.

Проверка источников не является клиническим утверждением приложения. У встроенных форм `source_review_status=verified`, `clinical_review_status=not_performed`. Шесть протоколов поддержки имеют статус `pending`; до документированного одобрения используется `safe_baseline`. Production не запускается без одобрения safety policy. Предварительные пороги Jev, словарь и окна предложений также требуют клинической проверки. Подробности — в [описании архитектуры](docs/ARCHITECTURE.md#материалы-и-границы-готовности) и [формате материалов](docs/MATERIALS.md).

Инициативные сообщения требуют отдельного согласия пользователя. Worker учитывает локальное время, паузы, активность, прочтение и лимиты. Конкретный push-провайдер не подключён: in-app сообщение сохраняется, push получает `not_configured`.

Обезличивание снижает риск передачи персональных данных и не гарантирует полного распознавания. Оператор отвечает за условия внешней обработки, права на материалы, инфраструктуру хранения и резервные копии.

## Разработка и проверка

```bash
poetry run pytest -q
poetry run ruff check .
poetry run ruff format --check .
```

Быстрые тесты используют временные SQLite-базы; девять проверок требуют отдельного PostgreSQL. **`TEST_DATABASE_URL` должен вести только в расходуемую тестовую БД: фикстуры удаляют и создают таблицы.**

Запуск вне Docker, изолированный PostgreSQL, миграции, live-прогоны и правила docstring — в [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md). Актуальные результаты и пределы проверки — в [docs/VERIFICATION.md](docs/VERIFICATION.md).

Управление памятью, сроком хранения, приватностью, контекстом и транзакциями описано в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Очистка по сроку хранения запускается оператором через `poetry run emo-config prune`; автоматически она не выполняется.
