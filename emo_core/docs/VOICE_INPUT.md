# Голосовые сообщения

Дополнение к текстовому чату от 13.11.2026. Требования исходного ТЗ к авторизации, Jev, безопасности и сохранению сообщений остаются общими; голосовой ввод передаёт в этот конвейер расшифровку.

## Обработка

1. Браузер записывает сообщение через MediaRecorder. Компактная кнопка микрофона находится в поле сообщения: удержание записывает до отпускания, короткий клик или Enter включает запись до повторного нажатия. Во время записи показаны анимация и таймер; после остановки доступны прослушивание, удаление и отдельная отправка. Отпускание кнопки само по себе ничего не отправляет. Выбор Deepgram/GigaAM вынесен в раздел «Модели», рядом с общими настройками AI. Отмена, смена профиля и разговора освобождают микрофон и удаляют черновик из памяти браузера. Позднее разрешение доступа не запускает запись после отмены или отпускания удерживаемой кнопки.
2. API проверяет JWT, владельца беседы, режим AI и согласия. Тело принимается потоком, максимум 8 МиБ; разрешены распространённые аудиоконтейнеры. FFmpeg декодирует только разрешённые форматы из pipe, без сетевых протоколов и пользовательских путей. Выход — mono PCM16, 16 кГц. Аудио не записывается на диск или в БД.
3. Deepgram Nova-3 распознаёт русский (`language=ru`), либо локальный Sherpa-ONNX запускает указанную модель GigaAM v3 E2E CTC INT8. Подмена результата mock при ошибке запрещена. Пустая и слишком длинная расшифровки отклоняются.
4. Срочные признаки в расшифровке сразу передаются в обычный safety pipeline, без Behavioral Signals. Затем программный отбор проверяет пригодность записи для анализа интонации; короткие и служебные реплики не вызывают внешний API эмоций. Для подходящих записей, при настройке и согласиях, используется Behavioral Signals v5: загрузка → ограниченное ожидание статуса → результаты. Ошибка этого дополнительного анализа даёт `unavailable`, сохраняя обработку текста.
5. `ChatEngine.send` получает обычный `MessageCreate` и доверенные серверные метаданные. Дальше используются те же Jev, ComplaintManager, PatientStateBuilder, StateEvaluator, выбор протокола, LLM, выходные проверки и память.

Сетевые запросы, FFmpeg и локальный inference выполняются вне транзакций БД. Дополнительных worker и брокеров нет. Лимит VOICE_CONCURRENCY резервируется до чтения тела: занятый процесс отдаёт 429, не загружая ещё одно аудио в память. Один экземпляр GigaAM лениво загружается на процесс API. Отмена HTTP-запроса не может остановить нативный inference: он остаётся единственным заданием модели, новые вызовы отклоняются до его завершения, очередь потоков не накапливается. FFmpeg завершается при отмене или превышении 15 секунд. Общий дедлайн чата действует отдельно после распознавания.

## Настройка

Ключи задаются в игнорируемом `.env` с правами `0600`. В `.env.example` — только пустые поля.

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `VOICE_ENABLED` | false | Включение голосового ввода |
| `VOICE_BACKEND` | deepgram | Исходный выбор распознавателя; общая настройка в БД имеет приоритет |
| `DEEPGRAM_API_KEY` | пусто | Серверный ключ Deepgram |
| `BEHAVIORAL_SIGNALS_API_KEY` | пусто | Token из Behavioral Signals API Keys |
| `BEHAVIORAL_SIGNALS_CLIENT_ID` | пусто | Числовой Client ID из той же строки ключа |
| `VOICE_MAX_BYTES` | 8388608 | Максимум тела запроса |
| `VOICE_MAX_SECONDS` | 90 | Общий предел длительности; GigaAM дополнительно ограничен 25 с |
| `VOICE_TIMEOUT_SECONDS` | 90 | Отдельный предел ожидания ASR и Behavioral Signals |
| `VOICE_CONCURRENCY` | 2 | Максимум одновременно обрабатываемых записей на процесс |
| `GIGAAM_MODEL_DIR` | models/gigaam-v3 | Каталог весов и tokens.txt |
| `GIGAAM_THREADS` | 2 | Потоки CPU распознавания |

Для локальной модели:

```bash
poetry install
poetry run emo-voice-model
poetry run alembic upgrade head
```

Команда скачивания получает только два файла из указанного репозитория Hugging Face и проверяет SHA-256. Сеть во время inference GigaAM не используется. Веса исключены из Git и Docker build context. В Compose API получает `./models:/app/models:ro`. Для сервера скачайте веса в эту папку до запуска контейнера; API UID 10001 должен иметь право их читать. Wheel содержит адаптер и команду загрузки; веса в wheel не включаются.

| Файл | SHA-256 |
|---|---|
| model.int8.onnx | 784d77aaa7a0899a247e72c71d667792087ee4dec985db1f57961767a5f6014f |
| tokens.txt | 142de7570b3de5b3035ce111a89c228e80e6085273731d944093ddf24fa539cd |

Для внешних сервисов необходимы AI_MODE=live, EXTERNAL_AI_ALLOWED=true, пользовательский external_ai_consent, сохранённое voice.external_audio_consent и флаг согласия текущего запроса. Сохранённое разрешение задаётся в «Настройки → Голосовые сообщения», флаг external_audio_consent передаётся при отправке каждой записи. Устаревшее окно с true не обходит отозванное разрешение в БД. После ASR согласия перечитываются: отзыв разрешения пропускает Behavioral Signals, но уже полученная расшифровка сохраняет обычную текстовую обработку. Режим из общей конфигурации в БД имеет приоритет над .env: mock/disabled не отправляют аудио провайдерам. GigaAM можно использовать без внешних согласий: Behavioral Signals тогда пропускается с consent_missing для подходящей записи.

В разделе «Модели» администратор меняет общий `voice_enabled` и `voice_backend` через существующий versioned runtime API, без перезапуска. Пользователь может отдельно выключить `voice.enabled` в настройках профиля: кнопка и черновик исчезнут, запись остановится, сервер отклонит новые голосовые запросы. Общий выключатель действует для всех профилей. Другие открытые окна получают конфигурацию при очередном опросе, не позднее обычного интервала 15 секунд. Секреты остаются на сервере; интерфейс показывает только наличие настроенных ключей. Изменение распознавателя применяется к следующей записи: уже записанный черновик сохраняет свой backend и UUID для корректного повтора.

Client ID находится в [кабинете Behavioral Signals](https://portal.behavioralsignals.com) → **API Keys**, в строке токена. UUID проекта Deepgram здесь не подходит. [Инструкция провайдера](https://docs.behavioralsignals.com/docs/create-a-project-and-api-token).

## API

Все маршруты находятся под `/api/v1/emo` и требуют JWT. Идентификатор владельца берётся только из JWT.

`GET /voice/config` возвращает выбранный backend, общую и личную доступность, согласия текущего пользователя, доступность дополнительного анализа, лимиты и `audio_retained=false`. Секретов в ответе нет. Не настроенный backend отключается в селекторе интерфейса. `PATCH /settings` принимает `voice: {enabled, external_audio_consent}`; эти предпочтения хранятся в существующем JSON настроек пользователя.

`POST /conversations/{id}/voice-messages` принимает **исходные байты аудио**, не JSON и не multipart. `Content-Type` соответствует записи, например `audio/webm;codecs=opus` или `audio/mp4`. Query-параметры:

| Поле | Значение |
|---|---|
| client_message_id | UUID, сохраняемый при повторе той же записи |
| backend | deepgram / gigaam |
| external_audio_consent | true / false, по умолчанию false |

Ответ соответствует обычной отправке текста: `user_message`, `assistant_message`, `replayed`. Расшифровка находится в `user_message.content`; краткие метаданные — в `user_message.metadata.voice`. Клиент не может передать собственные эмоциональные баллы через этот маршрут или через `MessageCreate`.

Повтор того же UUID, backend и SHA-256 использует сохранённую расшифровку. Уже готовый ответ чата возвращается повторно. Другая запись/беседа/backend с прежним UUID даёт 409. Пока первая обработка идёт, повтор даёт `voice_processing` (409); клиент сохраняет запись и прежний UUID. Сбои и отмены освобождают квитанцию. При падении процесса можно продолжить после истечения пятиминутной аренды; токен аренды запрещает старому запросу перезаписать результат нового. Между внешним успешным вызовом и фиксацией квитанции остаётся стандартное окно at-least-once: после падения в нём запрос провайдеру может повториться.

Миграция `e46b37a910cd` создаёт emo_voice_inputs: хеш, backend, состояние аренды, расшифровка и компактные метаданные. Последующая f70b1c4d9a82 добавляет два общих голосовых переключателя и отдельные снимки промпта. Текущая a184c6d2f903 добавляет счётчик повторов и индексы квот/аренды. Изменения пользователя сериализуются блокировкой настроек. Квитанции удаляются при удалении профиля и по общей retention policy. Принимается не более одной обрабатываемой записи на пользователя и 30 новых квитанций за час. Не более трёх попыток обработки одной неготовой записи; счётчик сбрасывается через час от последнего запуска. Готовый результат возвращается повторно без расходования попытки. Общий бюджет сообщений проверяется до оплачиваемого ASR; дополнительно действует ограничение процесса.

Для nginx добавлен отдельный location голосового маршрута с пределом 8 МиБ и ожиданием 600 секунд; общий маршрут оставлен с 240 секундами. Общий дедлайн чата по умолчанию 180 секунд, максимум 210, чтобы завершаться раньше proxy. При изменении VOICE_MAX_BYTES синхронизируйте предел nginx.

## Голосовой слой стейта

Отбор `voice-gate-1` не использует AI и не пытается распознать эмоцию по словам. Он пропускает анализ интонации при длительности менее 3 секунд, менее четырёх слов или 16 букв; также исключает приветствия/подтверждения/проверку микрофона, почти однословные повторы и ограниченный перечень полностью служебных вопросов. Неизвестная содержательная речь допускается. Служебное начало с содержательным продолжением не отбрасывается. Это инженерное ограничение качества и стоимости, не клиническая оценка. Даже «мне грустно», исключённое по длине из анализа интонации, проходит весь обычный текстовый конвейер и Jev. Срочный текст обрабатывается независимо от этого отбора.

В метаданных и отчёте сохранены версия отбора, причина, число слов, длительность, факт вызова Behavioral Signals и времена декодирования/ASR/эмоций. Текст не копируется в эти диагностические поля.

Behavioral Signals отдаёт envelope с `modelVersion` и `results`; `prediction[].posterior` содержит оценки четырёх классов: sad, angry, happy, neutral. Используются только валидные конечные значения, взвешенные по длительности неперекрывающихся фрагментов от 2 секунд. При нескольких говорящих принадлежность голоса пользовательнице не предполагается: возвращается `multiple_speakers`. Пол, возраст, ASR сервиса, embeddings и сырой ответ не сохраняются.

`patient_context.short.voice` содержит текущую запись и не более трёх доступных результатов суммарно за 72 часа, с источником, временем и версией модели. Пропуски/ошибки остаются в отчёте, но не занимают место наблюдений в стейте. Наблюдения отделены от JEV-маркеров и жалоб, не переносятся между беременностями и не трактуются как самоотчёт. Повтор давней сохранённой квитанции не обновляет время интонации. Время первой загрузки — серверное наблюдение, не доказательство времени физической записи в браузере.

Если в текущей записи доминирует sad/angry с posterior ≥0.6, обычный ответ получает инструкцию задать один бережный вопрос. Это инженерный фильтр неопределённых разговорных подсказок, не клинический порог или оценка выраженности симптома. Слова пациентки имеют приоритет; модель не должна утверждать чувства по голосу, спорить с отрицанием, делать диагноз или назначать лекарства. Голосовые баллы не меняют safety route, результат опросника, рекомендацию специалиста или факт выздоровления. Историческая запись сама по себе не запускает повторный вопрос.

## Диагностика и полный промпт

Отчёт под ответом показывает расшифровщик, решение отбора, вызов и результат Behavioral Signals, четыре оценки с версией модели, покрытие речью и время этапов. Отдельный блок объясняет выбранную потребность, запрошенный/применённый протокол, основания направления и голосового уточнения. Времена голосовой обработки и чата показаны отдельно.

Кнопка «Посмотреть промпт и переданный контекст» лениво загружает снимок через `GET /conversations/{cid}/messages/{assistant_id}/prompt`. Он содержит выбранную системную инструкцию и фактические role/content запросов генерации, повторной генерации и сжатия истории после обработки PrivacyBoundary. Для срочного шаблона запросов модели нет; в mock явно указан этот режим. Старые сообщения без снимка не реконструируются задним числом. В `LLM_EXTRA_BODY` дополнительные параметры сохраняются, но не могут заменить `model`, `messages`, `temperature` и `max_tokens`: отображаемый payload соответствует отправленному.

По запросу пользователя снимки сохраняются отдельно от обычных логов в emo_prompt_traces: zlib, SHA-256, максимум 8 МиБ до сжатия и 2 МиБ после. PROMPT_TRACE_ENABLED=false отключает сохранение; PROMPT_TRACE_RETENTION_DAYS=7 задаёт отдельный срок, от 1 до 30 суток. Просроченный снимок недоступен API сразу, физическая очистка выполняется worker ежедневно или командой emo-config prune. При превышении лимита отчёт явно сообщает об отсутствии снимка. Это приватные данные разговора; заголовки авторизации, API-ключи и внутренние рассуждения модели не собираются. Обычная история и polling содержат только небольшой манифест, а снимки не попадают обратно в стейт или контекст. Доступ требует JWT владельца конкретной беседы/сообщения, ответы запрещены кэшированию. Удаление исходных сообщений очищает также производные резюме и потенциально содержащие их более новые снимки. В stdout остаются только обезличенные технические коды, без текста и промптов.

## Приватность и проверка

Голос нельзя обезличить заменой имён в тексте, поэтому согласие на его передачу показано отдельно. Для Deepgram включены `mip_opt_out=true` и `redact_usage=true`. Текст после ASR проходит существующий PrivacyBoundary перед внешними Jev/LLM. Обещание «EMO не хранит аудио» относится к этому приложению; политика хранения у внешнего поставщика определяется его условиями и настройками аккаунта.

Интеграционные тесты используют подставные адаптеры только в явном test-режиме и проверяют фактический HTTP-контракт провайдеров через MockTransport. Отдельно проверены настоящее распознавание синтетической русской фразы Deepgram/GigaAM, Behavioral Signals с исправленным числовым Client ID и полный HTTP-путь Deepgram → отбор → Behavioral Signals → Jev/LLM → приватный снимок промпта. Провайдер вернул реальный результат модели 7.9.0. Физический микрофон и медицинские записи для проверки не использовались. Точный срез проверок: [VERIFICATION.md](VERIFICATION.md).

Источники: [поставка ONNX и контрольные суммы](https://huggingface.co/nocmt/GigaAM-v3-E2E-CTC-int8-ONNX), [short-form GigaAM до 25 секунд](https://github.com/salute-developers/GigaAM), [Deepgram Nova-3 и языки](https://developers.deepgram.com/docs/models-languages-overview), [данные Deepgram](https://developers.deepgram.com/trust-security/your-data), [redact_usage](https://developers.deepgram.com/docs/redact-usage), [загрузка Behavioral Signals](https://docs.behavioralsignals.com/docs/submit-audio-file), [результаты и posterior](https://docs.behavioralsignals.com/docs/get-results-after-completion), [статусы](https://docs.behavioralsignals.com/docs/check-the-processing-progress).
