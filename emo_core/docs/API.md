# Интеграция по API

Базовый префикс — `/api/v1/emo`. Точный контракт схем, обязательные поля и ограничения доступны в `/openapi.json`, интерактивная документация — в `/docs`. `demo/` и пример Python-клиента используют тот же REST API.

## Авторизация

Для пользовательских маршрутов передавайте:

```http
Authorization: Bearer <JWT-пользователя>
```

Основное приложение выпускает RS256 JWT с `sub` в формате UUID, `iss`, `aud`, `exp`, `iat`. EMO загружает публичные RSA-ключи по серверному `JWT_JWKS_URL`; URL из самого токена не используется. Значения издателя и аудитории должны совпадать с конфигурацией.

В development/test при явно включённой демо-авторизации доступны HS256-токены только профилей `anna` и `maria`. Их выдаёт `POST /dev/token` вне основного префикса. Если настроен вход по паролю, сначала вызовите `POST /auth/login` с `login`/`password`, затем передайте полученную сессию как Bearer при выпуске токена профиля.

Для `/admin/*` используется **`X-Admin-Token`**: значение `ADMIN_API_TOKEN` либо JWT сессии консоли в этом же заголовке. Обычный JWT пользователя административных прав не даёт. Сессия консоли в заголовке `Authorization` не заменяет `X-Admin-Token` для этих маршрутов.

Владельца пользовательских данных определяет только JWT. `user_id` в теле запрещён. Чужая и отсутствующая запись возвращают одинаковый 404. После `DELETE /data` профиль деактивирован; прежний JWT не создаёт его заново.

## Чат и повторы

Создать беседу: `POST /conversations`, например `{"title":"Разговор"}`. Ответ 201 содержит `id`.

```http
POST /api/v1/emo/conversations/<conversation_id>/messages
Authorization: Bearer <JWT>
Content-Type: application/json

{"content":"Мне хочется поговорить","client_message_id":"<UUID-клиента>"}
```

Ответ содержит `user_message`, `assistant_message`, `replayed`. Для сетевого повтора сохраняйте тот же UUID, текст и беседу. Ключ уникален в пределах пользователя: его повтор с другой беседой или текстом даёт 409. При уже готовом результате возвращается сохранённая пара; при обработке запрос ждёт её либо получает код конфликта ожидания. Прерванная обработка может продолжиться по тому же ключу.

Пока предыдущая реплика в беседе обрабатывается, новая получает 409 с `detail.code=previous_message_processing`. Дайте пользователю дождаться ответа. Конфликт ожидания исходной обработки может содержать `message_processing`.

`GET /conversations/{id}/messages` возвращает историю от новых к старым (`order=newest_first`). Для отображения по времени разверните страницу на клиенте. `POST /conversations/{id}/read` отмечает ответы ассистента прочитанными; это влияет на правила следующих инициативных контактов.

Отчёт находится в `assistant_message.metadata.decision_report` или по `GET /conversations/{id}/messages/{assistant_message_id}/decision-report`. У старого ответа без отчёта этот endpoint возвращает 404. Снимок моделей в отчёте относится к времени обработки; текущий глобальный выбор возвращает `GET /models`.

Журнал имеет собственные `days` 1–365 и `limit` 1–500, без offset; динамика — `days` 1–3650. У журнала `counts` относится ко всем найденным записям до ограничения, `truncated` сообщает об усечении.

## Настройки и согласия

`PATCH /settings` изменяет только переданные поля верхнего уровня. Для внешнего AI нужно личное `external_ai_consent=true`; для инициативности — `proactive_enabled=true`. Они не заменяют серверные разрешения. `push_enabled` отдельно разрешает push, но конкретный провайдер должен быть подключён оператором.

Перинатальный контекст основное приложение передаёт полями `pregnancy_id`, `estimated_due_date`, `gestational_week`, `birth_date`, `pregnancy_outcome`. При передаче недели EMO фиксирует её дату. Для `birth_date` и `proactive_paused_until` нужен ISO timestamp с часовым поясом; `estimated_due_date` — календарная дата. `country_code` выбирает контакты помощи, `timezone` задаётся именем IANA.

Личные разделы `privacy` и `context` сохраняются как переданные секции, а не как глубокое объединение с предыдущими настройками. Отправляйте все необходимые значения секции. Для `context` передавайте все три поля:

```json
{
  "context": {
    "compression": "auto",
    "input_target_tokens": 0,
    "keep_recent_messages": 12
  },
  "privacy": {
    "anonymize": true,
    "level": "standard",
    "protected_terms": []
  }
}
```

Цель `0` означает бюджет по окну; положительная не должна превышать серверный бюджет. `privacy:null`/`context:null` сбрасывает соответствующую личную секцию. Серверный режим маскирования и пределы возвращаются в эффективных настройках.

`POST /privacy/preview` с `{"text":"<синтетический пример>"}` возвращает `text` после маскирования и счётчики. Внешние модели не вызываются. API полного удаления и API очистки памяти имеют разные последствия; они описаны в [ARCHITECTURE.md](ARCHITECTURE.md#хранение-и-удаление).

## Опросники

Полный сценарий, тела запросов и ошибки — в [QUESTIONNAIRE_API.md](QUESTIONNAIRE_API.md). Кратко: получить редакцию → начать с `client_request_id` → сохранять ответы с `expected_revision` → завершить. Ответ — индекс варианта 0–3, не готовый балл.

Форму восстанавливайте из `questionnaire` сохранённой попытки. Safety guidance показывайте сразу при появлении флагов в черновике. Завершённый результат неизменяем; повтор завершения с теми же ответами возвращает прежний итог. Совместимый общий POST сохраняется для существующих клиентов.

## Ошибки

| Код | Значение для клиента |
|---|---|
| 401 | Нет действительной пользовательской или требуемой сессии консоли |
| 403 | Нет административного доступа |
| 404 | Ресурс отсутствует/чужой либо dev/административная возможность не настроена |
| 409 | Конфликт ревизии, ключа повтора, текущей обработки или неизменяемого результата |
| 410 | Данные профиля удалены, профиль деактивирован |
| 422 | Недопустимая структура, значения или конфигурация операции |
| 429 | Превышено число неудачных попыток входа |
| 500 | Внутренняя ошибка без раскрытия текста исключения |
| 503 | Ключ активной модели недоступен; требуется исправление конфигурации |

`detail` может быть строкой, списком ошибок валидации либо объектом с `code`; обрабатывайте эти формы. Ошибка генератора может дать успешный HTTP-ответ с сохранённым безопасным шаблоном: причина отражается в `origin` и отчёте, а не обязательно в HTTP-коде.

## Экономный polling сообщений

GET /api/v1/emo/conversations/{id}/messages возвращает дополнительный version — хеш состава страницы, включая беседу, limit/offset и UUID сообщений. При следующем запросе той же страницы клиент может передать known_version. Если состав не изменился, сервер возвращает unchanged=true и пустой items, без загрузки и передачи диагностических metadata. Клиент сохраняет показанную страницу. Удаление сообщения меняет version даже при прежнем последнем UUID. Версия отслеживает состав сообщений, а не изменения служебных read_at/metadata. При смене профиля или беседы клиент сбрасывает эту оптимизацию.

Голос, согласия, ограничения и просмотр приватного промпта: [VOICE_INPUT.md](VOICE_INPUT.md). Обычные запросы без known_version совместимы с прежним форматом items/order/limit/offset.
