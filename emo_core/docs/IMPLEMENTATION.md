## Дополнительные требования пользователя

- Отчёт решения хранится с ответом: Jev, причины, потребность, протокол, модели, ревизия, проверки и время. В stdout полный отчёт не выводится.
- Администратор управляет общими профилями LLM/Jev и режимом для следующих сообщений всех пользователей. Ключи хранятся в `.env` по ссылкам либо зашифрованы в БД; аудит не содержит их значений.
- Механизм шкал доступен через REST API. Вопросы, ключи и методы оценки сохранены отдельно; результаты считает Python.
- Есть личные настройки маскирования, контроль контекста, журнал состояния, календарное обновление перинатального контекста и различение ручной/автоматической паузы.

## Границы готовности

Проверка источников шкал не утверждает клиническое качество продукта. У форм `clinical_review_status=not_performed`; шесть протоколов — `pending`. Production блокируется до документированного одобрения safety policy; screening policy отдельно ограничивает автоматические предложения. Пороги и словарь требуют клинической проверки.

Конкретный push-провайдер не подключён; outbox честно отмечает `not_configured`. RLS не включена; scoping и ограничения БД покрыты тестами. Память обновляется синхронно. Обезличивание не гарантирует скрытие всех персональных данных. Текущая редактура не меняет эти границы; подробнее — в [ARCHITECTURE.md](ARCHITECTURE.md).
