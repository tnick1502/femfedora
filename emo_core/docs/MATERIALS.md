# Версионированные материалы опросников

Поставляемые опубликованные редакции и основания подключения: [questionnaires/RESEARCH.md](questionnaires/RESEARCH.md). Все вопросы, варианты, инструкции, периоды, индивидуальные ключи, пороги и источники находятся в `emo_core/questionnaires/*.ru.json`. Замороженная копия первой поставки — `alembic/data/questionnaires_20261110_v1.json`; её нельзя редактировать при следующих обновлениях.

Один JSON содержит `code` (`GAD7`, `EPDS`, `PHQ9`, `CITYBITS`), новую неизменяемую `version`, `language: ru`, `license_reference`, `definition`, `scoring_rules`, `enabled`.

Для произвольной новой редакции `definition` требует реального `clinical_review_status=approved`, `reviewed_by`, `approval_reference`. Проверка наличия полей не доказывает подлинность утверждения. Поставляемые редакции имеют отдельный честный статус `source_review_status=verified`, `clinical_review_status=not_performed`; это исключение принимается только при точном совпадении всего материала с библиотекой поставки, включая текст, ключи и ссылки. Произвольный JSON не может обойти проверку одним флагом verified.

`definition.items`: ровно 7/10/9/29 пунктов соответственно. Для PHQ/GAD/EPDS каждый: уникальный строковый `id`, точный `text`, четыре непустых строки `options` в исходном порядке и `score_map` из четырёх целых баллов (перестановка `[0,1,2,3]`). Для выбранной EPDS прямые пункты 1/2/4 имеют `[0,1,2,3]`, остальные `[3,2,1,0]`. Пункт 10 не переставляется и не оценивается как прямой. `timeframe_days` — 7 у EPDS, 14 у PHQ/GAD. Текст не редактируется LLM.

`definition.auxiliary_items` — отдельные пункты с `id`, `text`, `options`, `required`, `scored:false`. У PHQ-9 это необязательный `difficulty`. Он сохраняется в `auxiliary_answers` как индекс ответа и не прибавляется к сумме. У выбранного бланка GAD-7 дополнительного пункта нет.

`scoring_rules`:

- `maximum`: 21/30/27/93/60; минимум 0 у всех.
- `version`, `method:sum_of_item_score_maps`, `source_references` — воспроизводимость расчёта.
- `thresholds`: отсортированные диапазоны `minimum`, `maximum`, `code`, `label`; при наличии должны без пересечений и пропусков покрывать всю шкалу. Это описательная интерпретация источника, а не диагноз.
- `followup_score`: опциональный порог следующего шага (10 для GAD-7/PHQ-9/EPDS в данной поставке; у City BiTS нет общего диагностического порога суммы).
- `safety_items`: `{"item_id":"10","minimum_score":1}` у EPDS, `{"item_id":"9","minimum_score":1}` у PHQ-9. Для этих шкал обязателен независимый пункт безопасности. Сравнивается балл **после** score_map; сигнал проверяется и в черновике.
- `interpretation_note` сохраняет ограничения; `interpretation_authority` указывает происхождение политики. Нет вывода о диагнозе или процентах вероятности заболевания.

`definition.references` и `attribution` передаются в API и показываются на форме и в результате. Исходные PDF/URL/даты/хеши хранятся рядом с исследованием. Оператор отвечает за права на свою редакцию; импорт не создаёт лицензию автоматически.

Импорт после проверки: `poetry run emo-config import-questionnaire /path/to/approved.json`. Версия не перезаписывается. Успешный CLI-импорт отключает предыдущие активные редакции того же кода и языка в одной транзакции, сохраняя историю и снимки попыток. При публикации новой поставляемой версии добавьте новый файл, сохранив старый в библиотеке: проверка старых снимков опирается на точные хеши известных редакций. Не заменяйте старый файл другим содержимым. Для уже опубликованной PHQ-9 v1 при переходе на v2 сохранён точный SHA-256 замороженного материала первой миграции в HISTORICAL_BUNDLED_HASHES: старые черновики остаются проверяемыми, изменения текста не принимаются. Опубликуйте новый идентификатор и при необходимости отключите предыдущую в администрировании БД с аудитом оператора. Новые попытки отключённой версии запрещены; начатые используют собственный снимок и могут завершиться по нему. Если материал признан ошибочным и нужно отозвать начатые попытки, это отдельная управляемая процедура оператора, а не скрытое изменение ответов.

Снимок формы, хеш и результат фиксируются на попытке; после завершения результат неизменяем. Исправления создают новую редакцию для будущих измерений. Исторические результаты без подробного отчёта не пересчитываются задним числом. Полный контракт: [QUESTIONNAIRE_API.md](QUESTIONNAIRE_API.md).
