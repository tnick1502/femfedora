# Опросники через REST API

Базовый адрес: `/api/v1/emo`. Все вызовы требуют `Authorization: Bearer <JWT основного приложения>`. Владельца определяет проверенный JWT (`sub`); `user_id` в теле запрещён. `/dev/token` только для локального development/test. Никаких браузерных сессий или AI-провайдеров для расчёта не требуется. Swagger `/docs`, контракт `/openapi.json`.

| Вызов | Назначение |
|---|---|
| `GET /questionnaires` | Полные доступные редакции, вопросы, ключи, период, источники, ограничения |
| `GET /questionnaires/{id}` | Конкретная редакция, включая историческую отключённую |
| `POST /questionnaire-attempts` | Начать, опционально передав первые ответы; совместимая операция сохранения/завершения |
| `GET /questionnaire-attempts/{id}` | Продолжить: ответы, ревизия, снимок формы, прогресс, сигнал безопасности или итог |
| `PATCH /questionnaire-attempts/{id}` | Добавить/изменить часть ответов с проверкой ревизии |
| `POST /questionnaire-attempts/{id}/complete` | Проверить полноту и сохранить неизменяемый результат |
| `GET /questionnaire-attempts?status=in_progress&limit=30&offset=0` | Черновики; `completed` — завершённые, без status — все |
| `GET /next-actions` | Добровольные следующие действия с учётом расписания |
| `GET /trends` | Только завершённые суммы, сравнения только внутри одной редакции |

## 1. Получить редакцию

Выберите `id` из каталога. Для интерфейса используйте `definition.title`, `instructions`, `timeframe_days`, `items`, `auxiliary_items`, `attribution`, `validation_note`, `references`. Не меняйте порядок вариантов и не переводите формулировки самостоятельно. PHQ-9 имеет `usage=alternative_to_epds` и не должен автоматически предлагаться вместе с EPDS. Поле `definition_hash` идентифицирует точный материал (текст, ключ, интерпретацию и основания использования).

## 2. Начать

```http
POST /api/v1/emo/questionnaire-attempts
Authorization: Bearer <JWT>
Content-Type: application/json

{"questionnaire_id":"<UUID из каталога>","client_request_id":"<новый UUID клиента>"}
```

Ответ 200: `id`, `revision: 0`, `status: in_progress`, `questionnaire` (снимок), `answers: {}`, `progress`, `result: null`. Сохраняйте `id` и повторяйте исходный `client_request_id` при сетевом сбое; тот же запрос вернёт ту же попытку. Повтор ключа с другим начальным содержимым — 409. Ключ независим для каждого пользователя. Без ключа каждый POST создаёт новую попытку для совместимости; новым клиентам ключ настоятельно рекомендуется.

## 3. Сохранять и продолжать

```http
PATCH /api/v1/emo/questionnaire-attempts/<attempt_id>
Authorization: Bearer <JWT>
Content-Type: application/json

{"expected_revision":0,"answers":{"1":1}}
```

Возвращается `revision: 1`. Словари ответов объединяются с сохранёнными; отсутствующие ключи не стираются. Ответ — строго целое число 0–3, индекс отображаемого варианта, не балл; `true`, `1.0`, строки и неизвестные пункты отвергаются. Для PHQ-9 дополнительный пункт передавайте как `"auxiliary_answers":{"difficulty":2}`; он не входит в сумму. Для последующего сохранения используйте полученную ревизию.

`GET /questionnaire-attempts/<attempt_id>` возвращает эту же форму и ответы для восстановления на любом клиенте. Используйте `questionnaire` из попытки, а не новую форму из каталога: пользователь должен завершать ту редакцию, которую начал. Новые попытки отключённой редакции блокируются; уже начатая попытка завершается по сохранённому, проверенному снимку.

При любом сохранении проверяются пункты безопасности. Если `safety_flags` непустой, **сразу покажите `safety_guidance`**, даже если результат `null`. Не откладывайте сообщение до завершения теста. Сигнал безопасности сохраняется внутри попытки после изменения ответа. Это не означает, что сервис связался с врачом или экстренной службой.

## 4. Завершить

```http
POST /api/v1/emo/questionnaire-attempts/<attempt_id>/complete
Authorization: Bearer <JWT>
Content-Type: application/json

{"expected_revision":1,"answers":{"2":2}}
```

Для GAD-2 из предыдущего шага результат: сумма 3/6, `result.item_scores={"1":1,"2":2}`, действие `gad7_or_professional_assessment`, `not_a_diagnosis=true`. `result` также содержит диапазон, следующий шаг, ссылки, версию ключа, хеш редакции, время, `calculated_by=python`, `models_used=[]`. На экран выводите и сумму, и следующий шаг, и независимое `safety_guidance`; сообщение безопасности имеет приоритет, но не скрывает отчёт.

Неотвеченные обязательные пункты → 422 с `missing_item_ids`, итог не создаётся. Дополнительный функциональный пункт PHQ-9 необязателен. Повтор завершения без изменений возвращает исходный результат, даже если ревизия в повторном запросе устарела; ни баллы, ни дата, ни расписание не меняются. Изменение ответов завершённой попытки → 409; для нового измерения начните другую попытку. `PATCH` завершённой попытки всегда запрещён.

## Ошибки и конкурентность

- 401 — нет валидной авторизации.
- 404 — попытка не найдена или принадлежит другому пользователю; ответы одинаковы.
- 409, `detail.code=revision_conflict` — другой запрос уже изменил черновик; получите актуальную попытку и дайте пользователю проверить ответы. Не затирайте чужое изменение автоматическим повтором с новой ревизией.
- 409 — отключённая редакция, непроверенный материал, завершённая попытка или повтор ключа с другим содержимым.
- 422 — неверные типы/индексы/пункты или незавершённая форма.
- После сетевого сбоя запрос мог сохраниться на сервере: восстановите состояние через GET; начало и завершение допускают безопасный повтор с прежними идентификаторами.

Изменения пользователя сериализуются блокировкой его settings в PostgreSQL. Версия формы и история не зависят от переключения глобальных AI-моделей. В обычные логи ответы и медицинский текст не попадают; подробный отчёт доступен только через JWT владельца.

## Локальный Python-клиент

```bash
cp examples/client.env.example examples/client.env
chmod 600 examples/client.env
# Вставить свой EMO_API_TOKEN в examples/client.env
poetry run python examples/questionnaire_client.py --code GAD2
# Скрипт покажет вопросы и номера вариантов; вводятся индексы 0–3.
# Продолжить сохранённую попытку:
poetry run python examples/questionnaire_client.py --attempt <UUID>
```

Реализация клиента использует те же публичные endpoints, что и demo. Развёртывание описано в [README](../README.md), серверные секреты — в [CONFIGURATION.md](CONFIGURATION.md). Токен пользователя не является API-ключом LLM или Jev.
