# EMO Core — правила разработки

- Работать только внутри этого самостоятельного проекта; не импортировать код родительского проекта.
- Источник требований: docs/ORIGINAL_SPEC.md (дословная копия пользовательского задания).
- Перед каждым этапом сверять относящиеся к нему разделы ТЗ, после этапа обновлять docs/IMPLEMENTATION.md и запускать проверки.
- Любые пользовательские данные выбирать с user_id из проверенного JWT; запрещено доверять user_id из тела запроса.
- Сериализовать изменения одного пользователя блокировкой его settings; worker блокирует задания SKIP LOCKED и пользователя в том же порядке.
- Не логировать текст чата, ответы опросников, токены и исключения внешних провайдеров.
- Mock разрешён только явно и только development/test. Ошибка реального AI не должна превращаться в mock-результат.
- Клинические материалы, пороги и протоколы активировать только после документированного утверждения; не придумывать редакции опросников.
- Изменения проверять pytest, ruff и миграциями PostgreSQL; ограничения реальной проверки честно описывать.
