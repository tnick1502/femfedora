# Контракт ring health MVP v1

Исторический контракт. Текущая интеграция: [API v2](ring_health_v2_deployment_ru.md), [OpenAPI v2](ring_health_v2.openapi.json).

Вход и ответ — JSON. Функция Python: `src.ring_health.predict.predict(payload)`. CLI: `python -m src.ring_health.predict --input path.json --output result.json`. HTTP: `POST /v1/analyze`, health: `GET /health`, локальный адрес 127.0.0.1:8787. Максимальный размер тела HTTP — 2 MB. Все ML-выходы кольца имеют provenance=synthetic_only.

## Вход

Передаётся `as_of` в формате YYYY-MM-DD, `context` и либо `daily`, либо `oura`. Для контролируемого воспроизведения указывайте as_of явно. Без него используется дата последней строки. Наблюдения после as_of запрещены.

```json
{
  "as_of": "2024-04-10",
  "context": {
    "age": 32,
    "pregnant": false,
    "breastfeeding": false,
    "hormonal_medication": false,
    "hysterectomy": false,
    "bilateral_oophorectomy": false,
    "period_start_dates": ["2024-01-01", "2024-01-29", "2024-02-26", "2024-03-25"]
  },
  "daily": [
    {
      "date": "2024-04-10",
      "temperature_deviation": 0.15,
      "resting_hr": 57,
      "hrv_ms": 42,
      "respiratory_rate": 14.7,
      "sleep_minutes": 430,
      "sleep_efficiency": 89,
      "steps": 6700
    }
  ]
}
```

Короткий пример показывает схему, но не удовлетворяет требованиям истории. Полные работающие синтетические примеры: `data/samples/ring_health/menopause_demo_input.json` и `fertility_demo_input.json`; рядом сохранены ответы.

Если используется `oura`, объект содержит массивы `sleep`, `daily_readiness`, `daily_activity` из уже полученных пользователем экспортов APIv2. Если исходный endpoint возвращает `{data:[...],next_token:...}`, извлеките data и самостоятельно соберите все страницы. Сетевой доступ и OAuth токены эта реализация не запрашивает.

Все пять контекстных флагов должны быть явно false. Отсутствующее/неизвестное значение приводит к отказу. Это граница моделируемой популяции, а не утверждение, что true означает патологию. Возраст вне 18–65 лет не принимается. Демонстрационная фертильность обучалась только для возраста 22–43 года, модель стадии — 35–65 лет.

## История и единицы

- Одна строка на локальный день кольца. Дубликаты запрещены. Пропущенные даты восстанавливаются как пустые дни, не сжимаются.
- Температура — отклонение кожи в °C; абсолютная температура 36,5°C и значения в °F не подходят. ЧСС — уд/мин; HRV — мс; дыхание — в минуту; сон — минуты; эффективность сна — проценты; шаги — целое неотрицательное значение.
- null — пропуск; ноль не заменяет пропуск. Часть крайних диапазонов отсекается как ошибка единиц/внеобластные данные.
- Стадия: минимум 90 календарных дней и ≥70% валидных ночей по каждому сигналу за последние 28 и 90 дней. При max_probability < 0.60 выводится uncertain.
- Фертильность: минимум 35 календарных дней, ≥70% покрытия каждого сигнала за 28 дней и валидная температура в последних 3 днях; минимум 4 начала менструаций, то есть 3 завершённых цикла. Прошлые длины — 19–65 дней, текущий день — 1–60.
- Байесовская оценка дополнительно требует минимум 4 температуры в первых 6 днях текущего цикла и 3 после базы. Её собственный отказ не удаляет корректный ответ текущего ML-классификатора.

Пороговые диапазоны качества — инженерные правила демонстрации. Они не прошли клиническую валидацию. При сильной инфекции/лихорадке, смене часовых поясов или прибора возможны ошибки даже при достаточном покрытии.

## Выход

Верхний уровень содержит `mode=demonstration`, `medical_recommendation=false`, `validation_status`, `as_of`, покрытие и статусы.

`menopause_stage_demo.probabilities` — распределение трёх искусственных классов. `future_menopause_risk` и `time_to_menopause` всегда null: обученный и проверенный прогноз будущего события отсутствует.

`fertility_demo.fertile_day_probability` — вероятность принадлежности текущего дня интервалу ovulation−5..ovulation по синтетически обученному лесу. `postovulatory_signal_probability` — отдельный классификатор состояния не ранее ovulation+2. Это не вероятность беременности и не подтверждение овуляции.

`timing_distribution.forecast` — 7 дневных вероятностей из отдельной механистической модели. Квантили даты условны на овуляторный компонент, могут быть широкими; no_ovulation_component_probability — вероятность гипотезы симуляционной модели, не диагностический риск ановуляции. Две модели могут расходиться; автоматическое объединение не реализовано.

Частые статусы: `ineligible_or_unknown_context`, `age_missing_or_out_of_support`, `no_daily_data`, `out_of_range_values`, `insufficient_or_out_of_support`, `insufficient_recent_data`, `insufficient_cycle_history`, `cycle_history_out_of_support`, `scored`, `uncertain`. Некорректная структура или будущие данные дают HTTP 400. Ручная подача реальных данных не меняет provenance и не превращает модель в валидированную.
